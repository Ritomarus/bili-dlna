# bili-dlna：在 Quest 的 4XVR / Skybox 里直接刷 B 站

把哔哩哔哩"伪装"成局域网里的一台 DLNA 媒体服务器。戴上 Quest，在 4XVR 或 Skybox 的「网络 / DLNA」里打开 **Bilibili**，就能像翻本地文件夹一样刷推荐、热门、关注动态、收藏夹，看直播。播放器自带的影院环境、3D / 180° / 360° 模式都可以照常使用。

```
Quest (4XVR / Skybox) ──DLNA 浏览──▶ 本服务（电脑 / NAS）──▶ B 站接口
                      ◀──TS 视频流──  ffmpeg 合并音视频（不转码） ◀── B 站 CDN
```

## 运行环境

- Python 3.9 或更高版本（只用标准库，不需要 pip 安装依赖）
- ffmpeg（macOS：`brew install ffmpeg`；Windows：下载后加入 PATH）
- 运行本服务的电脑和 Quest 连在**同一个局域网**里（电脑最好插网线）

## 启动

```bash
./run.sh
```

或者：

```bash
python3 -m bilidlna
```

启动后会打印管理页面地址，例如 `http://192.168.1.10:8200`。

第一次运行时 macOS 可能会询问"是否允许 Python 接受传入网络连接"，请选择**允许**。

常用参数：

| 参数 | 说明 |
|---|---|
| `--port 8200` | HTTP 端口 |
| `--host 192.168.x.x` | 手动指定对外的局域网 IP（自动检测不对时使用） |
| `--name Bilibili` | 播放器里显示的服务器名称 |
| `--data ./data` | 登录信息和设置的保存目录 |
| `-v` | 输出详细日志 |

## 使用步骤

1. 在电脑浏览器打开管理页面，点**扫码登录**，用 B 站手机 App 扫码。不登录也能用，但最高只有 480P。
2. 在 Quest 里打开播放器：
   - **4XVR**：网络 / 局域网 → DLNA → Bilibili
   - **Skybox**：Network（网络）→ 找到 Bilibili（DLNA）
3. 浏览目录并点开视频：

| 目录 | 内容 |
|---|---|
| 推荐 / 热门 / 排行榜 | 每次进入都会刷新 |
| VR / 3D 专区 | 360° 全景、VR180、3D 左右格式的视频 |
| 关注动态 / 稍后再看 / 收藏夹 / 历史记录 | 需要登录 |
| 直播 | 我关注的（正在直播）、热门直播、VR 直播 |
| 搜索 | 在管理页面添加搜索词后，会出现在这里 |
| 手动添加 | 在管理页面粘贴 BV 号、视频链接、b23.tv 短链或直播间号 |

多 P 视频会显示成一个文件夹，里面是各个分 P。

## VR / 3D 视频

服务会根据标题自动识别 VR 格式，并在文件名里加上标签，4XVR / Skybox 按文件名自动切换模式：

| 标题包含 | 文件名标签 |
|---|---|
| VR180、180° | `_180_LR` |
| 360°、全景 | `_360` |
| 左右、SBS | `_LR` |
| 上下、TB | `_TB` |

如果识别错了，或播放器没有自动切换，在播放器里手动选择模式即可。这个功能可以在管理页面关闭。

## 画质设置（在管理页面修改）

- **最高清晰度**：默认 4K。4K 和 1080P60 需要大会员。Quest 的屏幕是 SDR，所以 HDR / 杜比视界的画面可能偏灰。
- **视频编码**：
  - HEVC（默认）：同等画质下码率更低
  - AVC：兼容性最好
  - AV1：Quest 3 可以硬解；Quest 2 不支持
- **直播编码**：默认 AVC。

## 实测性能（Mac + Quest，家庭局域网）

| 操作 | 结果 |
|---|---|
| 点开视频到收到第一个字节 | 0.2～0.5 秒 |
| 拖动进度条（按字节或按时间跳转） | 1～2 秒，音视频从同一个关键帧开始 |
| 直播起播 | 0.5～2.7 秒（取决于分配到的 CDN 节点） |
| 4K 吞吐量 | 通常 60～80 Mbps（4K 码率约 7～8 Mbps），实际取决于 B 站 CDN |
| 资源占用 | 不转码，CPU 很低；每路播放约 60MB 内存缓冲，不写硬盘 |

## 工作原理

- 读取 B 站 DASH 视频里的 `sidx` 分段索引，得到每个关键帧的时间和字节位置。拖动时音频和视频都从同一个关键帧开始，并按真实码率把"字节位置"换算成时间。
- 每一路播放是一个会话：同一个 ffmpeg 的输出放在内存滑动窗口里。播放器断开重连、续传时直接返回完全相同的字节，不会因为重新定位而出现时间戳倒退。
- 会话只比播放进度超前约 12MB，播放器断开 20 秒后自动结束。所以 4XVR 打开文件夹时批量探测视频，不会在后台持续下载。
- 本机中继负责给 CDN 请求补上 Referer，并处理断点续传、备用地址切换和播放地址过期。

## 常见问题

**播放器里找不到 Bilibili 服务器**
- 确认电脑和 Quest 在同一个网络里，并且路由器没有开"AP 隔离 / 访客网络"。
- 如果电脑开着 Clash / Surge 等代理软件的 **TUN / 增强模式**，可能会干扰组播。可以尝试：用 `--host` 指定电脑的局域网 IP；或者在代理软件里把 `239.255.255.250` 和局域网网段设为直连 / 排除。
- 检查 macOS 防火墙是否允许 Python 接受传入连接。

**视频打不开或一直转圈**
- 在电脑上用 VLC 打开 `http://<电脑IP>:8200/vod/BV1GJ411x7h7/0/test.ts`，排查是播放器的问题还是服务的问题。
- 运行时加 `-v` 查看详细日志。

**搜索提示"触发 B 站风控"**
- 服务会自动更换设备标识并重试。如果仍然失败，等几分钟再进入。

## 已知限制 / 后续计划

- 还没有弹幕：点播弹幕计划转成 ASS 外挂字幕，直播弹幕需要另外的方案。
- 付费内容、番剧和电影没有专门处理，可能无法播放。
- 目前只在 macOS + Quest 上测试过。Windows / Linux 理论上可以运行（只依赖 Python 标准库和 ffmpeg），但还没有验证。
